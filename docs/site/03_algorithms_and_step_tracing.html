03. Algorithmes & Traçabilité

Traceur hiérarchique, Gauss-Jordan, Gram-Schmidt, QR et Moindres Carrés

03. Algorithmes fondamentaux et Traçabilité hiérarchique

Le module linalg_pedagopy.algorithms regroupe les procédures fondamentales de l'algèbre linéaire appliquées selon l'approche de VMLS (Boyd & Vandenberghe) et des cours classiques de L1–L2.

Chaque procédure hérite de la classe de base Procedure et s'exécute dans un contexte de traçabilité pédagogique.

1. Moteur de traçabilité contextuelle (Tracer)

1.1 Pourquoi une traçabilité hiérarchique ? (Décision D6)

L'apprentissage de l'algèbre linéaire ne consiste pas seulement à obtenir une réponse numérique brute, mais à comprendre la succession d'étapes de calcul. Cependant, un niveau d'explication unique ne convient pas à tous les publics : - Un étudiant débutant a besoin de voir la réduction au même dénominateur lors d'une opération de ligne. - Un étudiant avancé ne souhaite voir que la matrice résultante à chaque pivot. - Un enseignant souhaite projeter les grandes étapes au tableau.

linalg_pedagopy résout ce dilemme par un traceur arborescent contextuel commandé par le context manager tracing :

Python
from linalg_pedagopy import Matrix, Vector, GaussJordan, tracing

A = Matrix([[2, 1], [4, 3]])
b = Vector([5, 11])

# Niveau 1 : Macro-étapes (étapes de pivot)
with tracing(level=1):
    res = GaussJordan(A, b).run()
print(res.explain())

# Niveau 2 : Micro-étapes (opérations élémentaires détaillées)
with tracing(level=2):
    res = GaussJordan(A, b).run()
print(res.explain())

1.2 Les 4 niveaux de zoom didactiques

Niveau Nom Description du contenu de la trace
0 Résultat seul Aucune trace intermédiaire ; seul le résultat final est retourné.
1 Macro-étapes Grandes phases : choix du pivot, passage en forme triangulaire supérieure, phase de remontée de Jordan.
2 Micro-étapes (recommandé) Opérations élémentaires sur les lignes (ACADEMIC_TOKEN_3), calculs de projections et normalisations.
3 Arithmétique élémentaire Détail arithmétique de chaque coefficient, calcul des produits scalaires terme à terme et simplification des radicaux.

1.3 Nœuds de l'arbre : Step, StepKind et Highlight

L'arbre de trace est composé de nœuds immuables Step. Chaque étape possède : - Un type d'action StepKind (ROW_SWAP, ROW_SCALE, ROW_ADD, PROJECTION, NORMALIZE, etc.). - Des instantanés matriciels (snapshot). - Une mise en valeur graphique Highlight spécifiant les coordonnées du pivot ACADEMIC_TOKEN_4, les lignes modifiées et la barre de séparation augmentée.

2. Élimination de Gauss-Jordan (GaussJordan)

La procédure GaussJordan résout les systèmes linéaires formels ACADEMIC_TOKEN_5 et calcule l'inverse de matrices carrées.

2.1 Signature et options

Python
GaussJordan(
    A: Matrix,
    b: Vector | Matrix | None = None,
    *,
    assumptions: Condition | None = None,
    strict: bool = True,
    compute_inverse: bool = False
)
  • A : Matrice des coefficients ACADEMIC_TOKEN_6.
  • b : Vecteur ou matrice du second membre (optionnel).
  • assumptions : Hypothèses initiales sur les paramètres de la branche.
  • strict : Si True, lève une exception en cas de système incompatible ou singulier au lieu de retourner un ensemble vide.
  • compute_inverse : Si True, calcule l'inverse via l'échelonnement simultané de ACADEMIC_TOKEN_7.

2.2 Typologie des ensembles de solutions

Le résultat renvoyé par GaussJordan.run() est un GJResult dont la propriété solution appartient à l'une des 3 catégories de SolutionSet :

ACADEMIC_TOKEN_0

  1. UniqueSolution : Système de Cramer ou système rectangulaire compatible de rang plein colonne.
    ACADEMIC_TOKEN_8.
  2. AffineSolution : Sous-déterminé ou système compatible de rang déficient.
    ACADEMIC_TOKEN_9. L'objet fournit la solution particulière ACADEMIC_TOKEN_10 et une base du noyau ACADEMIC_TOKEN_11.
  3. EmptySolution : Système incompatible (présence d'une ligne d'incompatibilité ACADEMIC_TOKEN_12 avec ACADEMIC_TOKEN_13).
    ACADEMIC_TOKEN_14.

2.3 Exemple avec paramètre et discussion automatique

Python
from linalg_pedagopy import Matrix, Vector, symbols, GaussJordan

m, = symbols("m")
A = Matrix([
    [1, 1, m],
    [1, m, 1],
    [m, 1, 1]
])
b = Vector([1, 1, 1])

res = GaussJordan(A, b).run()
print(res.explain())

Ce code produit automatiquement un CaseSplit distinguant : - Le cas ACADEMIC_TOKEN_15 : infinité de solutions (plan affine de dimension 2). - Le cas ACADEMIC_TOKEN_16 : système incompatible (ACADEMIC_TOKEN_17). - Le cas ACADEMIC_TOKEN_18 : solution unique ACADEMIC_TOKEN_19.

3. Substitutions Triangulaires

Pour les systèmes dont la matrice est déjà échelonnée, les algorithmes de substitution évitent le coût complet d'un pivot de Gauss :

  • ForwardSubstitution : Résout ACADEMIC_TOKEN_20 pour une matrice triangulaire inférieure ACADEMIC_TOKEN_21 (descente).
  • BackSubstitution : Résout ACADEMIC_TOKEN_22 pour une matrice triangulaire supérieure ACADEMIC_TOKEN_23 (remontée).
Python
from linalg_pedagopy import Matrix, Vector, BackSubstitution

U = Matrix([
    [2, 1, -1],
    [0, 3,  2],
    [0, 0,  4]
])
y = Vector([3, 8, 4])

res = BackSubstitution(U, y).run()
print(res.x)  # Vector([1, 2, 1])

4. Orthogonalisation de Gram-Schmidt (GramSchmidt)

La procédure GramSchmidt transforme une famille libre de vecteurs ACADEMIC_TOKEN_24 en une famille orthogonale ACADEMIC_TOKEN_25 puis orthonormée ACADEMIC_TOKEN_26 :

ACADEMIC_TOKEN_1

Python
from linalg_pedagopy import Vector, GramSchmidt

a1 = Vector([1, 1, 0])
a2 = Vector([1, 0, 1])
a3 = Vector([0, 1, 1])

res = GramSchmidt([a1, a2, a3]).run()

# Vecteurs orthogonaux
for u in res.orthogonal:
    print(u)

# Vecteurs orthonormés (avec radicaux exacts)
for q in res.orthonormal:
    print(q)

Détection de dépendance linéaire

Si la famille est liée, GramSchmidt lève une LinearDependenceError contenant un témoin de dépendance DependenceWitness détaillant la combinaison linéaire nulle.

5. Factorisation QR (QR)

La classe QR factorise une matrice ACADEMIC_TOKEN_27 de rang plein colonne sous la forme ACADEMIC_TOKEN_28, où ACADEMIC_TOKEN_29 a des colonnes orthonormales (ACADEMIC_TOKEN_30) et ACADEMIC_TOKEN_31 est triangulaire supérieure inversible.

Trois méthodes sont supportées : 1. method="gram_schmidt" : Gram-Schmidt classique ou modifié (forme symbolique naturelle). 2. method="householder" : Réflexions orthogonales de Householder (stabilité géométrique). 3. method="givens" : Rotations planes de Givens (idéal pour annuler des coefficients ciblés).

Python
from linalg_pedagopy import Matrix, QR

A = Matrix([
    [1, -1],
    [1,  0],
    [1,  1]
])

qr_res = QR(A, method="gram_schmidt").run()
print("Q =", qr_res.Q)
print("R =", qr_res.R)
print("Vérification Q @ R == A :", qr_res.Q @ qr_res.R == A)

6. Moindres Carrés Linéaires (LeastSquares)

La régression au sens des moindres carrés résout le problème d'optimisation : ACADEMIC_TOKEN_2

La classe LeastSquares calcule la solution exacte ACADEMIC_TOKEN_32 via : - La factorisation QR de ACADEMIC_TOKEN_33 : ACADEMIC_TOKEN_34. - Les équations normales : ACADEMIC_TOKEN_35.

Python
from linalg_pedagopy import Matrix, Vector, LeastSquares

A = Matrix([
    [1, 0],
    [1, 1],
    [1, 2],
    [1, 3]
])
b = Vector([1, 2, 2, 4])

ls = LeastSquares(A, b).run()
print("x_hat =", ls.x_hat)  # Estimateur des paramètres
print("y_hat =", ls.y_hat)  # Projection y_hat = A x_hat
print("r_hat =", ls.r_hat)  # Résidu r_hat = A x_hat - b
print("Norme au carré de l'erreur :", ls.residual_norm_sq)

# Vérification pédagogique fondamentale : A^T r_hat == 0
print("Orthogonalité du résidu :", ls.verify())  # True
