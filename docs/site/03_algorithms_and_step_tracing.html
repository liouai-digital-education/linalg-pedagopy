03. Algorithmes & Traçabilité

Traceur hiérarchique, Gauss-Jordan, Gram-Schmidt, QR et Moindres Carrés

03. Algorithmes fondamentaux et Traçabilité hiérarchique

Le module linalg_pedagopy.algorithms regroupe les procédures fondamentales de l'algèbre linéaire appliquées selon l'approche de VMLS (Boyd & Vandenberghe) et des cours classiques de L1–L2.

Chaque procédure hérite de la classe de base Procedure et s'exécute dans un contexte de traçabilité pédagogique.

1. Moteur de traçabilité contextuelle (Tracer)

1.1 Pourquoi une traçabilité hiérarchique ? (Décision D6)

L'apprentissage de l'algèbre linéaire ne consiste pas seulement à obtenir une réponse numérique brute, mais à comprendre la succession d'étapes de calcul. Cependant, un niveau d'explication unique ne convient pas à tous les publics : - Un étudiant débutant a besoin de voir la réduction au même dénominateur lors d'une opération de ligne. - Un étudiant avancé ne souhaite voir que la matrice résultante à chaque pivot. - Un enseignant souhaite projeter les grandes étapes au tableau.

linalg_pedagopy résout ce dilemme par un traceur arborescent : chaque appel à run() enregistre la trace complète (jusqu'au niveau 3) dans result.trace, et c'est au moment de l'affichage que l'on choisit le niveau de détail avec result.explain(level=...) (par défaut config.default_trace_level, qui vaut 1) :

Python
from linalg_pedagopy import Matrix, Vector, GaussJordan, tracing

A = Matrix([[2, 1], [4, 3]])
b = Vector([5, 11])

res = GaussJordan(A, b).run()

# Niveau 1 : macro-étapes (opérations de lignes et résultat)
print(res.explain(level=1))

# Niveau 2 : ajoute le choix des pivots et le découpage par colonne
print(res.explain(level=2))

# Niveau 3 : ajoute les contrôles de nullité de l'oracle
print(res.explain(level=3))

Le context manager tracing sert, lui, à regrouper dans un même arbre les étapes de plusieurs calculs successifs, filtrées au niveau indiqué :

Python
with tracing(level=1) as tr:
    GaussJordan(A, b).run()
    GaussJordan(A.T, b).run()
arbre = tr.tree          # Step racine contenant les deux réductions
print(len(arbre.children))

1.2 Les 4 niveaux de zoom didactiques

Niveau Nom Description du contenu de la trace
0 Résultat seul Seules les étapes de niveau 0 (en-tête de la procédure).
1 Macro-étapes (défaut) Opérations élémentaires sur les lignes (ACADEMIC_TOKEN_3) avec la matrice après chaque opération, résultat final.
2 Micro-étapes (recommandé en TD) Ajoute le traitement colonne par colonne, le choix et la stratégie de pivot, les projections et normalisations.
3 Contrôles élémentaires Ajoute les vérifications de nullité de l'oracle (CHECK) et les détails arithmétiques.

1.3 Nœuds de l'arbre : Step, StepKind et Highlight

L'arbre de trace est composé de nœuds immuables Step. Chaque étape possède : - Un type d'action StepKind (SECTION, INFO, WARNING, ROW_SWAP, ROW_SCALE, ROW_ADD, DOT, NORM, PROJECTION, SUBTRACT, NORMALIZE, BACK_SUBSTITUTION, CASE_SPLIT, CHECK, RESULT). - Des instantanés matriciels (snapshot). - Une mise en valeur graphique Highlight spécifiant les coordonnées du pivot ACADEMIC_TOKEN_4, les lignes modifiées et la barre de séparation augmentée.

2. Élimination de Gauss-Jordan (GaussJordan)

La procédure GaussJordan résout les systèmes linéaires formels ACADEMIC_TOKEN_5 et calcule l'inverse de matrices carrées.

2.1 Signature et options

Text
GaussJordan(
    A: Matrix,
    b: Vector | None = None,
    *,
    pivot_strategy: "simplest" | "first" | "partial" = "simplest",
    strict: bool = False,
    max_depth: int | None = None,
    max_cases: int | None = None,
    assumptions: Condition | dict | None = None,
    compute_inverse: bool = False,
)
  • A : Matrice des coefficients ACADEMIC_TOKEN_6.
  • b : Vecteur second membre (optionnel ; sans lui, seule la RREF de ACADEMIC_TOKEN_7 est calculée).
  • pivot_strategy : choix du pivot — le plus simple ("simplest"), le premier non nul ("first") ou le plus grand en valeur absolue ("partial").
  • strict : si True, lève SingularMatrixError pour un système incompatible (ou une matrice non inversible avec compute_inverse=True) au lieu de renvoyer EmptySolution / inverse=None.
  • max_depth, max_cases : limites de la discussion paramétrique (par défaut config.max_case_depth et config.max_cases).
  • assumptions : hypothèses initiales sur les paramètres de la branche.
  • compute_inverse : si True, calcule l'inverse via l'échelonnement simultané de ACADEMIC_TOKEN_8 (champ inverse du résultat).

Le résultat GJResult expose A, b, rref, augmented_rref, pivots, rank, free_vars, nullspace_basis, solution et inverse.

2.2 Typologie des ensembles de solutions

Le résultat renvoyé par GaussJordan.run() est un GJResult dont la propriété solution appartient à l'une des 3 catégories de SolutionSet :

ACADEMIC_TOKEN_0

  1. UniqueSolution : Système de Cramer ou système rectangulaire compatible de rang plein colonne.
    ACADEMIC_TOKEN_9.
  2. AffineSolution : Sous-déterminé ou système compatible de rang déficient.
    ACADEMIC_TOKEN_10. L'objet fournit la solution particulière x0 (ACADEMIC_TOKEN_11), une base du noyau basis (ACADEMIC_TOKEN_12) et les indices des variables libres free_vars ; at_params(t1, ..., tk) renvoie la solution pour des valeurs données des paramètres.
  3. EmptySolution : Système incompatible (présence d'une ligne d'incompatibilité ACADEMIC_TOKEN_13 avec ACADEMIC_TOKEN_14).
    ACADEMIC_TOKEN_15. L'objet indique la ligne témoin row (indice 0-based), la valeur non nulle witness du second membre et la liste inconsistent_rows.

2.3 Exemple avec paramètre et discussion automatique

Python
from linalg_pedagopy import Matrix, Vector, symbols, GaussJordan

m, = symbols("m")
A = Matrix([
    [1, 1, m],
    [1, m, 1],
    [m, 1, 1]
])
b = Vector([1, 1, 1])

res = GaussJordan(A, b).run()
print(res.explain())

for br in res.branches:
    print(br.condition, "->", br.result.solution)
# m ≠ 1 et m ≠ -2 -> UniqueSolution(x=(1/(m + 2), 1/(m + 2), 1/(m + 2)))
# m = -2 -> EmptySolution(ligne L3 : 0 = 3)
# m = 1 -> (1, 0, 0) + t_1·(-1, 1, 0) + t_2·(-1, 0, 1)

Ce code produit automatiquement un CaseSplit distinguant : - Le cas ACADEMIC_TOKEN_16 : infinité de solutions (plan affine de dimension 2). - Le cas ACADEMIC_TOKEN_17 : système incompatible (ACADEMIC_TOKEN_18). - Le cas ACADEMIC_TOKEN_19 : solution unique ACADEMIC_TOKEN_20.

3. Substitutions Triangulaires

Pour les systèmes dont la matrice est déjà échelonnée, les algorithmes de substitution évitent le coût complet d'un pivot de Gauss :

  • ForwardSubstitution : Résout ACADEMIC_TOKEN_21 pour une matrice triangulaire inférieure ACADEMIC_TOKEN_22 (descente).
  • BackSubstitution : Résout ACADEMIC_TOKEN_23 pour une matrice triangulaire supérieure ACADEMIC_TOKEN_24 (remontée).
Python
from linalg_pedagopy import Matrix, Vector, BackSubstitution

U = Matrix([
    [2, 1, -1],
    [0, 3,  2],
    [0, 0,  4]
])
y = Vector([3, 8, 4])

res = BackSubstitution(U, y).run()   # TriangularResult(x, A, c)
print(res.x)  # (1, 2, 1)

4. Orthogonalisation de Gram-Schmidt (GramSchmidt)

La procédure GramSchmidt (GramSchmidt(vectors, *, normalize="end", strict=False, assumptions=None)) transforme une famille libre de vecteurs ACADEMIC_TOKEN_25 en une famille orthogonale ACADEMIC_TOKEN_26 puis orthonormée ACADEMIC_TOKEN_27 :

ACADEMIC_TOKEN_1

Avec normalize="end" (défaut), les calculs restent rationnels jusqu'à la normalisation finale ; normalize="each" suit la présentation de VMLS (normalisation à chaque étape).

Python
from linalg_pedagopy import Vector, GramSchmidt

a1 = Vector([1, 1, 0])
a2 = Vector([1, 0, 1])
a3 = Vector([0, 1, 1])

res = GramSchmidt([a1, a2, a3]).run()

# Vecteurs orthogonaux (rationnels)
for u in res.orthogonal:
    print(u)          # (1, 1, 0) / (1/2, -1/2, 1) / (-2/3, 2/3, 2/3)

# Vecteurs orthonormés (avec radicaux exacts)
for q in res.orthonormal:
    print(q)          # (sqrt(2)/2, sqrt(2)/2, 0) / ...

Détection de dépendance linéaire

Si la famille est liée, GramSchmidt s'arrête au premier vecteur dépendant : le résultat a independent=False, dependent_index (indice 0-based) et un témoin DependenceWitness (witness) qui exprime ce vecteur en fonction des précédents. Avec strict=True, une LinearDependenceError est levée à la place.

Python
dep = GramSchmidt([Vector([1, 2]), Vector([2, 4])]).run()
print(dep.independent, dep.dependent_index)  # False 1
print(dep.witness)                           # a_2 = (2)·q̃_1

5. Factorisation QR (QR)

La classe QR factorise une matrice ACADEMIC_TOKEN_28 de rang plein colonne sous la forme ACADEMIC_TOKEN_29, où ACADEMIC_TOKEN_30 a des colonnes orthonormales (ACADEMIC_TOKEN_31) et ACADEMIC_TOKEN_32 est triangulaire supérieure inversible.

La factorisation est calculée par Gram-Schmidt (QR(A, *, strict=False, assumptions=None) ; il n'y a pas de paramètre method, ni Householder ni Givens). Le résultat QRResult fournit deux formes : - la forme orthonormée Q, R (avec radicaux) ; - la forme rationnelle sans radicaux Q_tilde, R_tilde, D_sq (colonnes orthogonales non normalisées, avec ACADEMIC_TOKEN_33), adaptée au calcul à la main.

Si les colonnes sont liées, full_rank vaut False et witness décrit la dépendance (ou LinearDependenceError avec strict=True).

Python
from linalg_pedagopy import Matrix, QR

A = Matrix([
    [1, -1],
    [1,  0],
    [1,  1]
])

qr_res = QR(A).run()
print("Q =", qr_res.Q)                 # colonnes (√3/3, √3/3, √3/3) et (-√2/2, 0, √2/2)
print("R =", qr_res.R)                 # [[√3, 0], [0, √2]]
print("Vérification Q @ R == A :", qr_res.Q @ qr_res.R == A)   # True
print("Q̃ =", qr_res.Q_tilde, " D² =", qr_res.D_sq)            # forme rationnelle

6. Moindres Carrés Linéaires (LeastSquares)

La régression au sens des moindres carrés résout le problème d'optimisation : ACADEMIC_TOKEN_2

La classe LeastSquares calcule la solution exacte ACADEMIC_TOKEN_34 via : - method="rational_qr" (défaut) : QR rationnelle sans radicaux, ACADEMIC_TOKEN_35 ; - method="qr" : QR orthonormée, ACADEMIC_TOKEN_36 ; - method="normal" : équations normales ACADEMIC_TOKEN_37.

Python
from linalg_pedagopy import Matrix, Vector, LeastSquares

A = Matrix([
    [1, 0],
    [1, 1],
    [1, 2],
    [1, 3]
])
b = Vector([1, 2, 2, 4])

ls = LeastSquares(A, b).run()
print("x_hat =", ls.x_hat)  # Estimateur des paramètres
print("y_hat =", ls.y_hat)  # Projection y_hat = A x_hat
print("r_hat =", ls.r_hat)  # Résidu r_hat = A x_hat - b
print("Norme du résidu :", ls.residual_norm)      # sqrt(70)/10
print("RMS du résidu :", ls.residual_rms)         # sqrt(70)/20

# Vérification pédagogique fondamentale : A^T r_hat == 0
# verify() renvoie une Explanation qui détaille le contrôle colonne par colonne
print(ls.verify())
